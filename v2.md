Implement the following improvements on the Antalya VIP Tourism website. Work in priority order. The main goals are to increase conversion rate, improve pricing consistency, strengthen SEO, and reduce booking friction.

## P0 — Critical fixes

### 1. Fix pricing / discount inconsistencies

The website currently shows conflicting discount messages such as `-15%` and `-25%`.

Remove these percentage-based discount claims.

Use a clearer pricing format such as:

`€50 per vehicle`
`Up to 7 passengers`
`Fixed online price`

Do not use discount labels such as "25% off" or "15% off" if the calculation is not consistent.

All prices should come from one centralized config/data source.

The same price should not be hard-coded separately in:

* homepage
* route pages
* booking form
* structured data
* meta descriptions
* SEO content

### 2. Review current base prices

Current base prices:

* Antalya City: €35
* Belek: €40
* Boğazkent: €45
* Side: €50
* Manavgat: €50
* Kemer: €55
* Kızılağaç: €60
* Alanya: €95
* Tekirova: €95
* Fethiye: €180
* Dalaman: €180
* Bodrum: €280

Tekirova currently looks expensive compared to the market.

Structure the pricing system so Tekirova can later be A/B tested around €70–75.

Alanya should also be easy to test at €90 vs €95.

Do not spread prices throughout the codebase. Create a single pricing source of truth.

# Implementation order

Implement in this order:

1. Create a centralized pricing source of truth
2. Remove all `15% / 25%` discount inconsistencies
3. Remove outdated hard-coded prices
4. Simplify the booking flow
5. Strengthen `per vehicle / up to 7 passengers` messaging
6. Move Meet & Greet / 777 information closer to booking
7. Synchronize structured data and metadata with pricing
8. Add or verify analytics funnel events
9. Prepare granular destination architecture
10. Build hotel landing page infrastructure

Do not break the existing booking system.

First inspect the current codebase and identify which files/components/services are affected.

Then implement changes in small, independent steps.

After each meaningful change, run:

* build
* lint
* typecheck
* existing tests

Add tests for critical new behavior where appropriate.

Avoid unnecessary refactoring.
